## Objective

Players retain the existing game and saves while developers work on a supported, reproducibly installed Vue interface whose reactive updates and packaged startup are covered by browser tests.

## Baseline and ownership

index.html currently loads Vue 2.6.12 from jsDelivr. components.js creates a Vue instance and registers global components; temp.js uses Vue.set. Vue 2 reached end of life on 2023-12-31, as confirmed by the official Vue notice. Existing template/global/reactivity assumptions must be inventoried before migration.

Existing source owners: [index.html](../../index.html); [js/components.js](../../js/components.js); [js/technical/systemComponents.js](../../js/technical/systemComponents.js); [js/technical/temp.js](../../js/technical/temp.js); [js/technical/canvas.js](../../js/technical/canvas.js); [style.css](../../style.css).
The [development guide](../developer-guide.md) owns local commands/navigation; update it in place when implementation changes those routes.

## Scope

- Migrate the real application to a supported Vue 3 release, pinning exact dependencies during preparation and preserving static/local hosting.
- Replace Vue 2 construction/global registration/reactivity APIs and affected template/event/lifecycle assumptions using the official migration guidance.
- Serve/package the pinned runtime from the application artifact rather than fetching it from a runtime CDN; update real/test boot paths together.
- Verify reactive game updates, save flows, keyboard interaction, layout and packaging against the existing browser baseline.

Excluded:

- A new visual design, progression/balance changes, new accounts/backend services or save-format/key changes.
- Paid Vue support, hosting changes, production deployment or mandatory purchase of tools/services.
- Keeping Vue 2 and Vue 3 as parallel production modes, a permanent compatibility build, or test-only substitution that conceals the shipped dependency.

- **UI01-AC04:** Browser fixtures cover fresh and representative early/middle/late saves, prestige/reset, purchase/automation, layer/tab selection, notifications, save/export/import/rename/select and error recovery. Values, controls, navigation context and valid saved progress match the behavioral baseline, with no unexpected console or migration warnings.
- **UI01-AC05:** Rendered checks verify keyboard access/focus through changed controls, readable feedback, supported desktop and narrow layouts, and canvas/tree resizing after tab/window changes. Preserve existing interactions; record any unavailable accessibility/actual-user evidence without claiming synthetic tests prove usability.
- **UI01-AC06:** Tests execute the same Vue version and boot path as the delivered artifact. Replace the TST01 Vue 2-specific local routing/fixtures where necessary, verify they cannot continue serving the old runtime, and run current rule/static/browser checks in CI against the integrated package.

Existing save formats/key and Decimal semantics are unchanged; smoke-load recoverable baseline fixtures and document rollback to the prior code artifact without destructive data conversion.
- **UI01-AC08:** The development guide identifies app/component owners, packaging/start/test commands, generated artifact sources and external dependencies. Record before/after representative startup/tick/render measurements for the same fixture and environment, without inventing a performance target or claiming improvement without data; publish an unmerged PR with known limits.
